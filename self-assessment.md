# Professional Self-Assessment

Completing the Computer Science program and building this ePortfolio has helped me consolidate both technical capability and professional readiness by showing not only what I can build, but how I evaluate, improve, and communicate about software. Across coursework and my professional role in healthcare and pharmacy informatics, I have had consistent exposure to real constraints such as uptime expectations, data sensitivity, and stakeholder needs. The capstone experience reinforced that professional software development is not just writing code. It is making design decisions, managing trade-offs, validating behavior, anticipating failure modes, and communicating outcomes clearly to different audiences.

Collaboration and stakeholder communication are core strengths I bring into computer science work. In my work environment, I regularly interact with multiple groups with different priorities, including clinical and operational stakeholders, IT partners, and vendors. Translating requirements into actionable tasks requires structured communication and a clear understanding of risk. Throughout the program, I practiced this same skill set through project planning, peer-facing discussion work, documentation, and iterative improvement based on feedback. This portfolio includes a code review intended for a peer or manager audience to demonstrate how I explain existing functionality, identify improvement opportunities, and justify enhancements in a way that supports decision-making.

This ePortfolio also demonstrates my ability to apply algorithmic thinking and computer science practices within a realistic system. For the algorithms and data structures category, I implemented filtering, sorting, and pagination for the tutorial listing endpoints. Even though these features are common, they require careful validation and predictable execution paths. I used allow-listed fields, controlled sort directions, and structured parsing of query parameters so the API behaves consistently while avoiding invalid inputs. Pagination was implemented through page and pageSize calculations that translate to skip and limit behavior, improving efficiency by retrieving only the records needed for a given request.

For software design and engineering, I improved the structure and maintainability of the API by separating application configuration from server startup logic, which also improves testability. I implemented centralized error handling to standardize responses and reduce the likelihood of sensitive internal information being exposed. I added input validation and field allow-listing for create and update operations to improve correctness and reduce unexpected persistence of invalid data. I also added automated tests using Jest and Supertest to verify core API behaviors and prevent regressions. These steps reflect professional engineering practices used in industry, including modular design, consistent interfaces, and repeatable verification.

For the databases category, I strengthened the persistence layer by improving data integrity and query performance within MongoDB using Mongoose. I added schema-level constraints such as required fields, default values, and string length limits to enforce consistent data quality. I configured update operations to enforce validation rules so that modifications cannot bypass constraints. I also designed and applied indexes to support common filtering and sorting patterns, improving query efficiency and reinforcing the importance of aligning database design to real access patterns.

A security mindset is integrated across the portfolio. In software systems, especially in healthcare contexts, trust boundaries and data integrity cannot be assumed. This portfolio demonstrates security-oriented decisions such as explicit validation of inputs, limiting allowed query parameters, and implementing consistent error responses that reduce information leakage. It also reflects a mindset of anticipating common adversarial or failure scenarios like malformed requests, unexpected payloads, and unsafe query construction. Security was treated as part of the design and implementation process rather than a final add-on.

## How the artifacts fit together

This portfolio uses one backend API artifact enhanced across three categories to demonstrate growth in software engineering, algorithmic reasoning, and database engineering. The code review establishes the baseline and planned improvements, and the three enhancement narratives show progressive improvement in structure, correctness, performance, and data integrity. Together, the artifact and supporting documentation demonstrate program outcome achievement through collaborative communication, professional-quality written and visual presentation, algorithmic problem solving with trade-offs, effective use of industry tools and techniques, and a consistent security mindset.
